## Purpose

Provide distributed tracing for the Philobiblos backend so that every HTTP request, database call, and cross-service interaction can be correlated and inspected in an observability backend.

## ADDED Requirements

### Requirement: HTTP requests are traced
The system SHALL emit a trace span for every incoming HTTP request and include the request path, method, and status code as span attributes.

#### Scenario: Successful API request is traced
- **WHEN** a client makes an HTTP request to any `/api/*` endpoint
- **THEN** the trace contains a server span with the request path and method
- **AND** the span status reflects the HTTP response status code

#### Scenario: Failed API request is traced
- **WHEN** an API request results in a 4xx or 5xx response
- **THEN** the trace contains a server span with the corresponding HTTP status code
- **AND** the span is marked with an error status

### Requirement: Database operations are traced
The system SHALL emit trace spans for Entity Framework Core database operations and include the command text and target table as span attributes.

#### Scenario: Query is traced
- **WHEN** a handler executes a database query
- **THEN** the trace contains a child span describing the database operation
- **AND** the span includes the command text or operation name

### Requirement: Correlation IDs are propagated
The system SHALL attach the existing correlation ID to the active trace span so that logs and traces for the same request can be correlated.

#### Scenario: Correlation ID in trace
- **WHEN** a request includes a correlation ID (or one is generated by the middleware)
- **THEN** the trace span for that request includes the correlation ID as an attribute
- **AND** downstream spans share the same correlation ID attribute

### Requirement: Traces are exported to a collector
The system SHALL export traces to a configured OpenTelemetry collector endpoint using OTLP over HTTP or gRPC.

#### Scenario: Traces reach the collector
- **WHEN** the application is configured with a valid OTLP exporter endpoint
- **THEN** generated traces are sent to that endpoint
- **AND** no traces are lost when the collector is temporarily unavailable
